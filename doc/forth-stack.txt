*forth-stack.txt*  Experimental Forth stack visualization in Neovim

Requires Neovim >= 0.10. Tested on Linux x86-64, Neovim 0.10.4, Gforth 0.7.3.

QUICK START                                               *forth-stack*

Install lucianobianc/forthstackplugin using native packages or a plugin manager.
With start packages, commands load automatically without setup.
The demo does not need Python or Gforth: >
    :ForthStackDemo
<
Install Python 3 and Gforth on PATH. Opening a .fs file starts tracing
automatically. To start or resume a run manually: >
    :ForthStackRun
<
HEALTH CHECK                                              *forth-stack-health*
>
    :checkhealth forth-stack
<
COMMANDS                                                  *forth-stack-commands*

:ForthStackAnalyze        Analyzes documented definitions once without execution.
:ForthStackDemo           Opens the bundled example with a recorded trace.
:ForthStackRun [word]     Without an argument, runs the file. With an argument,
                         also calls that word after loading the file. Both
                         modes follow edits.
:ForthStackStop           Pauses updates and cancels the current buffer's run.
:ForthStackStatus         Opens the status and full error in a text window.
                         Use q to close or :write /tmp/forth-stack-error.txt
                         to save the message.
:ForthStackLoad {json}    Loads an external version 1 or 2 JSON trace.
:ForthStackInspect        Inspects the cursor token, falling back to its line.
:ForthStackInline         Shows the cursor token stack until the cursor moves.
:ForthStackInlineToggle   Toggles continuous inline display for this buffer.
:ForthStackAutoToggle     Toggles automatic .fs tracing for the session.
:ForthStackToggle         Hides or shows the loaded data.
:ForthStackClear          Clears data and cancels the current buffer's run.

In file mode, runtime stacks follow top-level literals and calls. Definitions
with documented effects show independent symbolic stacks seeded from the input
names, even without calls. Declaring a word never executes its body. Inline and
Inspect prefer symbolic states where available; other recorded body observations
are marked "last call". Set symbolic=false to disable automatic analysis.
Uncalled definitions do not execute their bodies.

After Run, stacks update after 350 ms without new edits, including in Insert
mode and without saving. Edits cancel the previous run. Automatic errors are
available in Status without repeated notifications while typing.
Stop/Clear pause; Run resumes. Renaming/closing also disables automatic updates.
No command writes the buffer or imposes global keymaps.

CONFIGURATION                                             *forth-stack-setup*
>
    require('forth-stack').setup({
      python = 'python3',
      gforth = 'gforth',
      timeout = 5,
      max_events = 10000,
      max_depth = 256,
      symbolic = true,
      auto_start = true,
      inline = false,
      auto_update = true,
      debounce_ms = 350,
    })
<
setup() is optional with normal packages, registers commands, and is repeatable.
For a copy added to runtimepath after startup, call setup().
With lazy.nvim, use main = 'forth-stack' and opts = {} in the plugin spec.

python and gforth must be executable names or paths, without arguments.
The maximum limits are 60 seconds, 10000 events, and 256 cells per snapshot.
The typing delay debounce_ms accepts integers from 1 to 5000 milliseconds.

API                                                       *forth-stack-api*

setup(opts?)             Configures the plugin and registers commands.
demo()                   Opens the example with bundled trace data.
run(entry?, bufnr?)      Runs a buffer snapshot and enables automatic updates.
                        An omitted or empty entry selects file execution.
status(bufnr?)           Returns the status and last error, if any.
status_view(bufnr?)      Opens a readable diagnostics split; returns its buffer.
stop(bufnr?)            Cancels a run; returns true if one was active.
load(path, bufnr?)       Reads, validates, and displays a trace.
show(trace, bufnr?, base?) Displays an already decoded trace table.
clear(bufnr?)           Cancels execution and removes data.
toggle(bufnr?)          Returns the new visibility, or false without a trace.
inspect(bufnr?, line?)  Returns an inspection window, or nil without observations.

The default buffer is the current one. The API raises errors; commands notify.

LABELS                                                    *forth-stack-labels*

Use a normal single-line Forth comment to label the top stack element: >
    17 ( LABEL: age )
    dup 1+
<
The result is [ age:17, age:18 ]. Copies have distinct IDs and retain their
source label. Inspect shows copy origins. Labels follow dup, over, swap, rot,
nip, tuck, drop, and unit increment/decrement (1+, 1-, 1 +, 1 -).
Comparisons create unlabeled results; unsupported transformations may clear
labels. Names must match [A-Za-z_][A-Za-z0-9_-]{0,63}. A label on an empty stack
reports an error. Labels persist in source comments, not in a separate file.

See doc/labels.md and examples/labels.fs for the full example and limitations.

LIMITATIONS                                               *forth-stack-limits*

Virtual text shows the last after observation on each line, with the top on the
right. The suffix 'after TOKEN' does not promise the state at the end of the
whole line. Per-line history is retained; occurrence navigation is not available.
Basic identities and labels are supported through ( LABEL: name ) comments.
Companion-file persistence and interactive label assignment are not implemented.

Immediate words and the internals of preexisting code have limited coverage.
Execution uses a private buffer snapshot, without saving. It is not a sandbox.
The buffer needs a name in an existing directory; includes use files on disk.
Each update reruns the program, including I/O effects. Successful observations
from a validated Forth failure can remain marked "before error"; status stays
error. Other failed results are not displayed. Automatic failures appear as
diagnostics and in Status; manual failures also notify. Changes to auxiliary files during a run are not detected.

JSON: at most 4 MiB, 10000 events, and 256 cells. Integers outside ±(2^53-1)
are rejected to avoid rounding. Source validation compares tokens/positions,
not complete source contents. Generate a new trace after changing the program.
Collection captures stdout/stderr in memory and is unsuitable for large volumes.
Cancellation terminates the supervisor and its direct Gforth child; additional
processes launched by the program are not managed.

Read README.md, doc/neovim-display.md, and doc/gforth-instrumentation.md in the
repository for installation, protocol details, and the full investigation.

CURSOR STACKS

Inline display defaults to off. A token already represented by the visible
end-of-line annotation does not receive a duplicate inline stack.
:ForthStackInline shows the cursor token's stack
until the cursor moves. If no trace exists, it runs the file once without arming
updates. :ForthStackInlineToggle enables or disables cursor-driven inline stacks
in the current buffer. Set inline=true in setup() to enable it by default.
:ForthStackInspect selects the token under the cursor, falling back to the line.
Repeated tokens show their most recent execution; unexecuted tokens and whitespace
have no inline stack. Cursor annotations are shared between windows showing the
same buffer. Inline annotations never modify the source. No keys are mapped.

AUTOMATIC START

Opening a .fs file starts tracing by default, including updates after edits.
:ForthStackAutoToggle switches this behavior off/on for the session, pausing or
resuming .fs buffers. Set auto_start=false in setup() to start only on command.
:ForthStackStop pauses the current buffer until :ForthStackRun resumes it.
The separate auto_update=false option disables updates after edits.

SYMBOLIC ANALYSIS AND ERRORS

Use :ForthStackAnalyze for one analysis without running the file. It pauses
execution; :ForthStackRun resumes it. Symbolic inputs come from ( in -- out )
comments following definition names. Analyzed output counts are checked against
the declaration, then matching positions receive the output names. These are
symbols, not concrete values. Supported: basic stack/arithmetic/comparison words,
earlier declared contracts, and simple IF/ELSE/THEN. Unsupported operations,
loops, recursion, variable effects and non-data stacks stop analysis with a notice.
Contract depth errors warn. See doc/symbolic-analysis.md for full boundaries.

Actual failures produce Neovim error diagnostics at the responsible call (red in
standard themes). Use :lua vim.diagnostic.open_float() to read the full message.
Validated observations before a Forth failure may appear marked "before error";
execution status stays error. A corrected run clears the error. Editing and Clear
remove stale results. Failed JSON imports remain rejected.

OPTIONAL KEYS

Suggested buffer-local normal mappings: <localleader>s for ForthStackInline,
<localleader>i for ForthStackInlineToggle, and <localleader>r for ForthStackRun.
The plugin assigns none. Check :verbose nmap <localleader>s for existing maps.
Use a FileType=forth autocmd and vim.keymap.set with buffer and desc options;
README.md has a complete example. which-key can show the descriptions when used.
